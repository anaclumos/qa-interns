# Test suite and CI

- `package.json`, `bunfig.toml`, and the tests set no per-test timeout, so `bun run test` or `bun test <file>` fails the Docker tests at Bun's 5000 ms default and the timed-out test's `finally` then fails later tests, for example through a leftover `QA_INTERNS_SUBNET`; pass `--timeout 1200000`, the value `ci.yml` passes, to any local run of a Docker test.
- The `test` script runs `bun test --parallel=2` by measurement: four workers made each end-to-end test 2.2 to 3.3 times slower through Docker daemon and build contention and pushed the replay test past the 1200 s timeout with `devcontainer up` killed at exit 143, while the longest test under two workers took 979 s; raise `--parallel` only after a run shows every test under the timeout, and split a long file's tests instead. [source: https://github.com/anaclumos/qa-interns/pull/229]
- Bun does not cancel the body of a test that hits `--timeout`, so its run keeps going and its end calls `forgetSecrets()` through `guard` in `src/run.ts` while the next test of the same file runs; that test then fails a redaction assertion or prints `# Unhandled error between tests`, so read the first `this test timed out` line and any `devcontainer up ... exited with 143` before you debug redaction. [source: https://github.com/anaclumos/qa-interns/issues/242]
- `test/suite-lock.ts` starts `bun test` as a child and forwards no signal, so killing `bun run test` or a `timeout` around it leaves the suite running and holding `$XDG_RUNTIME_DIR/qa-interns/suite.lock`; send SIGTERM to the `bun test` PID itself, whose run guard tears its environments down and exits 130, and never SIGKILL it, because SIGKILL skips `afterAll` and leaves mounted output disks.
- `flock()` in `src/logins.ts` runs the `flock` binary on an inherited descriptor and the binary exits, so `/proc/locks` and `lslocks` name an exited PID for `suite.lock`; find the real holder by scanning `/proc/*/fd` for `suite.lock`. [source: https://github.com/anaclumos/qa-interns/pull/199]
- Setting `QA_INTERNS_SUBNET` for a whole suite run breaks the tests that assert the default `10.213.0.0/16` mapping (`slotSubnets`, `renderOverride`, the relay address); a test that needs another range sets it for one check with `withSubnet` in `test/environment.test.ts` and takes a block with `freeBlock` from `test/subnet.ts`. [source: https://github.com/anaclumos/qa-interns/pull/70]
- `test/fake-agent.mjs` takes the first `http://` URL in the prompt as the target, reads every `{...}` object with string `id` and `title` as a listed finding, and reads the first json code fence as the seeded account, so a new line in `src/prompt.ts` that adds an earlier `http://` URL, such an object, or a json code fence changes what the end-to-end tests do.
- A failed environment start reports `devcontainer up for <project> exited with 1: An error occurred starting Docker Compose up (log: <run dir>/envs/<name>/env.log)` and keeps Compose's own error only in `env.log`, and the end-to-end tests delete their whole `qair-f-e2e-<id>` root in `afterAll`, so copy `envs/*/env.log` while a failing test still runs.
- The `ci.yml` `test` job downloads `docker-compose` with `curl -fsSL` and no retry, so an HTTP 502 or 503 from github.com fails the job at the `Install Docker Compose 5.5.1` step before any test runs; rerun the failed job.
