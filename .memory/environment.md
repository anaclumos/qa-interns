# Environment, Compose, and output disks

- `loadTarget` renders the checks with `docker compose ... --profile "*" config`, which lists every profiled service, while a service is active only when a second `config` without `--profile`, named with `service` plus `runServices`, lists it (`src/target.ts`); Compose reads `COMPOSE_PROFILES` from the `.env` beside the first `-f` file, not from the working directory, so compute `active` only from that second selection. [source: https://github.com/anaclumos/qa-interns/pull/41]
- Teardown runs `docker compose down --rmi local`, which skips an image with a custom `image:` name or a `build.tags` entry, and then removes only `qa-<runId>-*` and `vsc-qa-<runId>-*` images, so every build path writes only the run's own names (`buildImages` overrides `image` and `build.tags`, `renderOverride` sets `build: !reset null` for a prebuilt service) and a service the run does not start never reaches a build; any other name leaks for good. [source: https://github.com/anaclumos/qa-interns/pull/29]
- Compose merges the generated `compose.qa.yml` into the target's files by key, so a target's own `logging` options, a target network named `qa_internal`, `qa_relay`, `qa_agent`, or `qa_egress` (for example with `driver: macvlan`), or its `build.tags` survive unless `renderOverride` writes `!override`, or `!reset` for `ports` and `build`; a new generated key that a target can also set needs the same tag. [source: https://github.com/anaclumos/qa-interns/pull/49]
- Target services reach the relay for `egress` hosts through `extra_hosts` entries, never through a Docker network alias on the relay, because a container resolves its own alias to itself and the relay would dial itself in a loop. [source: https://github.com/anaclumos/qa-interns/pull/23]
- `bind()` in `src/environment.ts` sets `create_host_path: false`, because Compose otherwise creates a missing mount source as a root-owned directory, which can land inside a login store that neither the intern nor the host user can then use or remove. [source: https://github.com/anaclumos/qa-interns/pull/2]
- Docker creates the missing parents of a bind mount inside the runner's tmpfs home as root with mode 0755, so Codex fails `initialize` with `failed to initialize sqlite state runtime` and Chrome fails with `chrome_crashpad_handler: --database is required`; a provider that mounts below the home lists every parent in its `tmpfs` array in `src/providers.ts`, parents before children, as the OpenCode entry does. [source: https://github.com/anaclumos/qa-interns/issues/1]
- `watchOut` counts the 1 GiB output disk as full below 16 MiB free (`fullBelow`) or at 0 free inodes, and a test that fills the disk needs a time box above 30 seconds on CI.
- A tmpfs Docker volume (`--opt type=tmpfs`) loses its files when no container mounts it, so the output disk holder container (`qa-interns.out` label, name `<project>-out`) stays until `saveDisk` copies the files into `interns/<id>/out` with `docker cp <holder>:/out/. -` piped to `tar -x`; a `bun test` that is killed leaves the holder and its volume, which `qa-interns down <run dir>` or `docker rm -f <holder> && docker volume rm <holder>` removes. A rootless Docker daemon cannot loop-mount (`losetup: Permission denied`, `/dev/loop*` owned by `nobody`) and its mounts never reach the host, so every host-side read of `/qa/out` goes through `pullDisk`. [source: https://github.com/anaclumos/qa-interns/pull/46]
- The seed step appends its raw output to `env.log` before `keepSeedSecrets` adds the seed values to the secret set, so redaction at write time in `capture` replaces a `secrets.hostEnv` value inside a longer seed secret and the end-of-run `redactFiles` pass then misses the rest; leave `capture` logs raw for that pass, and redact a new output file outside `envs/` and `interns/`, such as the run-root `build.log`, in the code that writes it. [source: https://github.com/anaclumos/qa-interns/issues/214]
- The Dev Container CLI writes override values as unquoted YAML with `$` unescaped, so a line break in a value injects keys and `${HOME}` becomes a host bind, and `devcontainer read-configuration` differs from what Docker receives; validate the rendered Compose files with and without the CLI's files after `devcontainer up` through `devContainerViolations` in `src/target.ts`, and re-check every service, exempting the build overrides that Dev Container features add with host paths. [source: https://github.com/anaclumos/qa-interns/pull/17]
- GNU `tar -T -` treats a listed name that starts with `-` as an option, so a working-tree file named `-C` changes the directory; the `--dirty` export in `exportTree` passes `--no-recursion --null --verbatim-files-from -T -`, and a test file list keeps names such as `-C` and `sp ace`. [source: https://github.com/anaclumos/qa-interns/pull/72]
- `Bun.JSONL.parse` in Bun 1.4.2 returns the values before a malformed line and drops the rest with no error, so `readRelayLogs` parses each line with `JSON.parse` and `relaySchema.parse` and a corrupt line fails the report; do not swap `Bun.JSONL.parse` in.
- The kernel charges file pages to the first cgroup that reads them, so the first runners on a newly built runner image show 400 to 550 MiB more page cache in `memory.peak` than runners on a warm image; to measure a runner change, compare `memory.stat` `anon` beside `memory.peak` and run before and after on images of the same age. [source: https://github.com/anaclumos/qa-interns/issues/205]
