# agent-browser in the runner

- Each `agent-browser --session <name>` is its own Chrome, and the runner's `pids_limit: 4096` counts threads: an idle session holds about 18 processes and 250 tasks, a session on a real app about 680 tasks, and a same-site tab adds 1 process and 12 tasks, so six real sessions reach the limit, the kernel logs `cgroup: fork rejected by pids controller`, and the intern ends `failed` with `opencode acp exited with 134:` and nothing after the colon or with `spawn shell in /qa/out: Resource temporarily unavailable (os error 11)`; the prompt's "memory for about four at once" bounds memory, not processes, so count the intern's sessions before you blame the model or the adapter. [source: https://github.com/anaclumos/qa-interns/issues/223]
- agent-browser 0.38.1 starts each session's daemon from its own canonicalized binary, so a wrapper in place of the `agent-browser` binary never intercepts the daemon; the session name is the last `--session`, else `AGENT_BROWSER_SESSION`, else the config file, else `default`; `agent-browser session list --json` still lists a session about 100 ms after `close` returns, so code that counts live sessions right after a `close` polls first; re-verify these from the agent-browser source when `runner/Dockerfile` bumps it. [source: https://github.com/anaclumos/qa-interns/issues/223]
- The runner sets no `AGENT_BROWSER_ALLOWED_DOMAINS` and passes no `--allowed-domains` on purpose: with a non-empty list, agent-browser 0.38.1 runs every Worker and SharedWorker from a `blob:` bootstrap, so `self.location` inside a worker loses its query and fragment, replaces `RTCPeerConnection` with a constructor that throws, and rejects `--profile` and `--state`, so interns report bugs no visitor sees; the isolated networks and the proxy allowlist in `src/providers.ts` confine the browser instead. [source: https://github.com/anaclumos/qa-interns/pull/109]
- agent-browser splits `AGENT_BROWSER_ARGS` on commas and newlines, so `--disable-features=A,B` becomes stray startup URLs and Chrome exits; any non-flag argument there is a startup URL that makes `--allowed-domains` fail, `--in-process-gpu` crashes Chrome in the runner, and the `NetworkServiceInProcess2` feature ends the whole browser on a network-service fault. [source: https://github.com/anaclumos/qa-interns/issues/205]
