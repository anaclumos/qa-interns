# Run lifecycle, interrupts, and redaction

- `capture(cmd, { timeout })` in `src/target.ts` wraps the command in `timeout --kill-after=10s`, which signals only its direct child, and `capture` also waits for stdout to close, so a descendant that ignores SIGTERM and holds stdout keeps it waiting past the timeout; Bun's own `timeout` spawn option has the same gap, so a command whose descendants can outlive it starts `detached: true` under `trackGroup` and gets `process.kill(-pid, "SIGTERM")` and then `"SIGKILL"` 10 seconds later, as `seatStore` in `src/logins.ts` does. [source: https://github.com/anaclumos/qa-interns/pull/106]
- `stop()` in `src/run.ts` calls `killCommands()`, which also kills the `docker image rm` and `docker compose down` of a teardown that already started, so a signal during the `reporting` phase records `teardown failed: ... exited with 143`, skips `redactFiles`, and exits 130 while the Docker objects can still end up removed; a probe of the interrupt path sends the signal during `reporting` and reads `state.json` and the redaction result, not only the Docker leftovers. [source: https://github.com/anaclumos/qa-interns/issues/238]
- `killCommands()` runs only from the signal handler, so a run stopped with SIGKILL leaves its `docker compose` or Dev Container startup command running, reparented to PID 1, and that command can create Docker objects after the next run's sweep tore the run down and deleted its `$XDG_RUNTIME_DIR/qa-interns/runs/<runId>` file; remove them with `qa-interns down <runId>`. [source: https://github.com/anaclumos/qa-interns/issues/248]
- `qa-interns run` handles SIGINT, SIGTERM, and SIGHUP and exits 130 on each, and a process with a SIGHUP handler still receives SIGHUP under `nohup`, so a run started with `nohup` ends when its SSH session hangs up; start a long run as a transient user unit with `systemd-run --user`.
- `writeTickets` hard-links each evidence file into `tickets/<group>/` through `linkEvidence` in `src/findings.ts`, so a ticket shares the inode that `redactFiles` rewrites in place; any earlier write of the report, such as a snapshot before teardown, leaves out the tickets, and `writeTickets` stays after `redactFiles` in `src/run.ts`. [source: https://github.com/anaclumos/qa-interns/issues/191]
- `forms()` in `src/secrets.ts` covers a secret's raw value, its JSON escape, its double JSON escape, and its control-stripped value only, so a secret that agent-browser records URL-encoded or as a form body with `+` for spaces, such as a login body in a HAR file under `interns/<id>/out/`, stays unredacted.
- `latestRunDir` in `src/state.ts` parses the `state.json` of every directory under the runs directory, so one run written by an older schema, such as one without `options.confirmConcurrency`, or a directory without `state.json` makes bare `status`, `report`, and `down` exit 1 with `<file> is invalid` or `No run state at <file>`; move such a directory out of the runs directory or name the run explicitly, and add no `.default()` or `.optional()` to the schema. [source: https://github.com/anaclumos/qa-interns/issues/159]
