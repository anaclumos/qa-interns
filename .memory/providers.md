# Providers and agent adapters

- The ACP SDK's `LineBuffer` keeps every read without a newline as its own object, about 73 bytes of heap per read, so a byte limit alone does not bound memory against an adapter that writes one byte at a time; keep the transform in `src/acp.ts` that joins reads into one buffer per newline or per `heldReads` (1024) reads before the SDK sees them. [source: https://github.com/anaclumos/qa-interns/pull/40]
- The Codex entry in `src/providers.ts` sets `INITIAL_AGENT_MODE: "agent-full-access"` because Codex's own sandbox cannot start in the unprivileged runner container, whose isolation is the boundary; do not switch Codex to a sandboxed mode. [source: https://github.com/anaclumos/qa-interns/pull/2]
- `OPENCODE_PERMISSION` in `src/providers.ts` puts `"*": "deny"` first because later keys override earlier ones, so a built-in tool an intern needs joins the allow list or the model never sees it; `invalid` stays allowed because OpenCode repairs malformed tool calls through it, `websearch`, `question`, and `skill` stay denied, and under a `gpt-` model `write` and `edit` become `apply_patch` under the same `edit` permission; check a change with `opencode debug agent build` in the runner image, which prints a denied tool as disabled. [source: https://github.com/anaclumos/qa-interns/pull/143]
- The runner sets `OPENCODE_DISABLE_MODELS_FETCH=true`, so OpenCode reads only the models.dev snapshot built into its binary; an OpenCode bump in `runner/Dockerfile` confirms the configured model id is in that binary (`grep -a -c '<model id>' <opencode binary>`), that the provider's npm package is in OpenCode's `BUNDLED_PROVIDERS`, because a runtime install from the npm registry is blocked by the proxy, and that a live `opencode acp` turn through `QA_PROXY_ALLOW=<host> node runner/proxy.mjs` contacts only `opencode.ai` or `openrouter.ai`; a denied `registry.npmjs.org` there comes from a background plugin install that only logs a warning, so that host never joins the allowlist. [source: https://github.com/anaclumos/qa-interns/pull/186]
- About a third of the OpenCode MiMo confirming interns' time-up turns write no `confirmation.json` because the model flips between two answers for minutes; rewording the time-up prompt, a `null` value for an untried attempt, and OpenRouter `reasoning.effort` or `max_tokens` did not change that, `reasoning: { enabled: false }` wrote `task: false` for an untried task, and only a longer turn helped, which is why `writeUpMs` in `src/run.ts` is 4 minutes; measure a new prompt against stored transcripts before you change it. [source: https://github.com/anaclumos/qa-interns/pull/251]
- `@agentclientprotocol/claude-agent-acp@0.81.2`, pinned in `runner/Dockerfile`, offers only model aliases such as `sonnet` and `opus` in its `model` config option, so a Claude login whose `model` is a full id such as `claude-sonnet-5-5` fails the intern; read `configOptions` from `session/new` in the runner image before a model value goes into a logins file. [source: https://github.com/anaclumos/qa-interns/pull/141]
